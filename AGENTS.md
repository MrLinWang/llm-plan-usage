# Repository Guidelines

## Project Overview

`llm-usage` is a Python 3.11+ CLI that unifies usage monitoring for multiple LLM coding-plan / token-plan platforms (Kimi Code, Volcengine Ark Coding + Agent plans, Ollama Cloud, OpenCode Go, ClinePass, and a local LLM Gateway). All seven registered platforms are fetched live over HTTP via `httpx`. Results render as a color-coded `rich` table, with SQLite history snapshots and JSON output for scripting. Beyond the seven built-in keys, any platform section keyed `<base>#N` (N≥2, e.g. `kimi#2`) is an independent **provider instance** of that type — separate credentials/display name/visibility/card, addable & deletable by both admin and regular users. Three frontends share the same fetch pipeline: `show` (one-shot rich table), `tui` (live-refresh terminal dashboard), and `web` (FastAPI browser dashboard, per-platform cards).

## Architecture & Data Flow

Flat layered design with one-way data flow:

```
cli.py (click group: show/tui/web/config/history)
  → config.load_config()                    # TOML at ./config.toml (cwd)
  → providers.fetch_all(cfg)                 # ThreadPoolExecutor, one thread per enabled platform
      → _prepare_config() per platform       # inject _platform_key, resolve display_name, expand env: api_key
      → Provider.fetch(config_section)       # live: httpx sync; config supplies credentials
          → returns PlatformResult(entries=[UsageEntry...], error=None|str)
  → show: display.render_results() / results_to_json()   # rich Table+Panel or JSON
    tui: display.build_overview() under rich.Live, cbreak key loop (q/r/+/-)
  → web: web.create_app() → FastAPI; UserCaches(TTL per-config-hash pool) wraps fetch_all;
         session-cookie auth gates every route (users/sessions in history.db;
         site toggles like registration_enabled / allow_user_providers in settings table);
         per-user dashboard merge (own config + shared platforms with (owner) suffix);
         /api/usage → display.results_to_dict(); pages serve static/*.html; PWA assets via unauthenticated routes
  → store.save_snapshot(results)            # SQLite, skips errored platforms (show only)
```

Key abstractions:
- **`Provider` Protocol** (`providers/base.py`): `runtime_checkable` protocol — `name`, `display_name`, `is_manual` attrs + `fetch(config) -> PlatformResult`. Providers return errors inside `PlatformResult.error`, never raise.
- **`UsageEntry` / `PlatformResult`** (`models.py`): the single contract every provider produces and display/store consume. `PlatformResult.ok` is `error is None`.
- **Registry** (`providers/__init__.py`): `PROVIDERS` dict maps 7 platform keys → provider instances. Volcengine registered twice (`volcengine-coding`, `volcengine-agent`) — same class, different config sections. Config sections keyed `<base>#N` are instances of the base type: `fetch_all` dispatches them to `PROVIDERS[base]` (unknown base keys skipped silently) and re-sorts by `(platform_order(base), registry(base), N)`; `UsageEntry`/`PlatformResult` carry the full instance key downstream (snapshots, shares, display).
- **Error isolation**: `fetch_all` wraps each `fetch` in `_run` which catches all exceptions → `PlatformResult(error="内部错误")` (deliberately generic; the actual traceback goes to the log via `logger.exception`, never into the user-facing string). A single platform failure never breaks the batch. Results merged per platform in submission order, then re-sorted to config/registry order.
- **Multi-credential plans (non-Gateway)**: kimi / volcengine×2 / ollama / opencode-go / clinepass accept a `credentials` list — each item (`name` + credential fields) is an independent billing plan. `fetch_all` fans out one concurrent `_run` per credential (`_credential_specs` builds sub-configs with the slot's resolved keys), then merges per platform in submission order: entries get tagged `UsageEntry.plan` (= slot `name`, default `套餐N`); per-credential failures join as `warning` (partial) or `error` (all failed). A section resolving to a **single** credential — legacy top-level keys or a lone slot (named `套餐1` by the web slot editor or anonymous) — stays one plain fetch with `plan=None`: partition headers appear only with ≥2 plans. LLM Gateway keeps its groups handling and is never expanded.
- **Concurrency**: `ThreadPoolExecutor` (sync `httpx.Client`), not asyncio — avoids asyncio dependency spread.
- **Elastic worker pool**: `fetch_all` sizes the pool as `min(max(1, len(tasks)), 16)` (tasks = platforms × credential slots); pass `max_workers=` to pin it (tests do).
- **Dependency injection**: `httpx.Client` is constructor-injected into live providers (`client=None` → own client created/closed per `fetch`). Tests pass `httpx.MockTransport`-backed clients.
- **Shared serialization**: `display.results_to_dict()` is the single JSON shape consumed by both `--json` output (`results_to_json` wraps it) and the web API (`/api/usage`).
- **Web TTL cache**: `web.UserCaches` is a per-config-hash TTL pool — each distinct config (`load_config()` for admin, `store.get_user_config()` for regular users) gets its own `UsageCache` (clamped `[5, 3600]`s, one lock across the fetch so concurrent requests share a result), capped at 32 entries with oldest evicted; identical configs share one cache. `get()` keys by `sha1(json.dumps(config, sort_keys=True))` so edits invalidate by hash mismatch (no `set_config` invalidation). The browser page re-fetches `/api/usage` on the same interval and ticks countdowns client-side every second.
- **Scoped cache invalidation**: `UserCaches.invalidate_for(config)` invalidates only the entry matching one config's hash; `/api/refresh` uses it instead of `invalidate_all`, so one user's manual refresh no longer discards other users' cached results.
- **Multi-user isolation**: usage is private by default; single-admin model. Admin's platform config = `config.toml`; regular users' configs live in `history.db` `user_configs` (JSON `{"platforms": {key: section}}`), fully isolated from config.toml. `/api/usage` merges per user: own results first (own platforms keep bare names, own share rows skipped), then `store.list_shared_platforms(username)` (owner-sorted) — each shared result gets a `(owner)` `display_name` suffix on a `dataclasses.replace` copy (never mutating the shared cache entry); **same-key name collisions keep every source** (distinct suffixes, e.g. `Kimi Code(admin)` + `Kimi Code(alice)` coexist; own bare-name platform is a separate card). Visibility per platform is 3-state (private / public / shared-to-users), stored as `user_shares` rows (`"*"` = public); admin PUT `/api/config/platforms/{key}` and regular-user PUT `/api/my/platforms/{key}` both accept `visibility` `{type, targets}` (validated: type enum, targets exist and ≠ self, deduped; public/private reject targets). Custom `display_name`: both PUT endpoints accept it on **every** platform (empty = keep current value; 64-char cap enforced by `_validate_platform_fields`) — the custom name shows on the owner's dashboard (and `show`/`tui`) and inside the `(owner)` suffix seen by share targets. Regular users get `/api/my/platforms` (full editor: enabled + credential slots / gateway base_url+groups / visibility, stored in their own `user_configs`, admin → 400); `GET /api/users` is `api_user` (regular users need the share-target list), mutations stay `api_admin`. Deleting a user cascades their `user_configs` and both directions of `user_shares`.
- **Web auth**: Session-cookie auth gates every route — pages 302 to `/login`, APIs 401 (`api_user` dependency) / 403 (`api_admin`). Zero users → `needs_setup`, and `/api/auth/setup` creates the first admin. Roles: admin (user management + provider credential config) vs regular user (dashboard + own provider credential config); regular users' own-provider editing is gated by the `allow_user_providers` site toggle (default on — absent/"1" allowed, only explicit "0" blocks, `/api/my/*` → 403, read-only usage APIs unaffected); **single-admin model — `POST /api/users` rejects `is_admin: true` (400, all created users are regular; the users page has no admin checkbox), the admin can never be deleted**; every user can change their own password (invalidates their other sessions). Open registration: admin toggles `registration_enabled` via `GET`/`PUT /api/settings` (stored in the `settings` table, default off); when on, `POST /api/auth/register` creates a regular user and logs them in immediately (session cookie, same as setup). Passwords hashed with stdlib `hashlib.pbkdf2_hmac` (SHA-256, 600k iterations, 16-byte salt, `hmac.compare_digest`) — stored as `pbkdf2_sha256$iters$salt$dk` in the `users` table. Sessions are `secrets.token_urlsafe(32)` rows in the `sessions` table with 7-day TTL (lazy expiry on read/create; persist across restarts). Cookie `llm_usage_session`: `httponly`, `samesite=lax`, `path=/`; all mutation endpoints accept JSON bodies only (cross-site forms can't construct JSON → no CSRF token). Deleting a user or resetting a password deletes that user's sessions.
- **Web hardening**: login/register/setup throttle per client IP (`_LoginLimiter`: 5 failures within 60s → 300s lockout, HTTP 429; counters are in-process and cleared on success); usernames validated against `[A-Za-z0-9_.-]{1,64}`; `/api/auth/setup` creates the first admin atomically via `store.create_first_admin` (`BEGIN IMMEDIATE` serializes concurrent setups — no count-then-create race); response headers hardened by middleware (`X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`); session cookie gains `Secure` when env `LLM_USAGE_SECURE_COOKIE=1`; error payloads never echo exception details (500 body is generic, detail goes to server logs).
- **Web credential config**: Admins edit per-platform `enabled` + credentials at `/config`. Non-Gateway platforms (`kimi`/`ollama`/`opencode-go`/`clinepass`/`volcengine-*`, per `web.CREDENTIAL_FIELDS`) use **credential slots** — each slot = one billing plan; views expose `credential_slots` (`[{index, name, credentials:{field: masked}}]`, synthesized slot 0 from legacy top-level keys, `[]` when nothing set; JS renders one empty slot by default). PUT with `credential_slots` validates (`_validate_credential_slots`: index/name/duplicate checks, empty value = keep existing, env-ref non-empty, per-slot completeness — `api_key` or AK+SK), writes the canonical `credentials` array (default names `套餐N`), then clears the top-level credential fields via `_clear_top_level_credentials` (write-then-delete). Top-level field PUTs (e.g. `{"api_key": "sk-new"}`) keep the legacy behavior and leave an existing `credentials` array untouched. LLM Gateway additionally exposes a `groups` view/edit for shared-quota API-key groups (masked keys, add/remove group, replace/keep a key by index) plus an editable `base_url` (gateway-only PUT field, empty = keep). PUT merges via `config.update_platform_config()` (TOML save); cache invalidation is hash-driven (next `get()` sees the new config hash). Views never return plaintext: `env:` values pass through as-is, literal keys show `first4…last2` (`••••` if shorter than 8 chars); an empty input means "keep current value". `tier`/`limits` (and gateway `usage_path`) stay hand-edited in `config.toml`.

```bash
# No Makefile, no lockfile.
```

## Code Conventions & Common Patterns

- **Type hints**: PEP 604 union syntax (`float | None`, `dict[str, Any]`). Every module starts with `from __future__ import annotations`.
- **Error handling**: Providers catch their own errors and return `PlatformResult(error=...)` — the string is user-facing Chinese (`"未配置"`, static auth hints like `"认证失败(401)..."`). Network/unexpected failures are deliberately generic (`"网络错误"`, `"内部错误"`, `"HTTP {status}"`) — exception details go to server logs via `logging`, never into client-visible strings. The registry's `_run` adds a final `except Exception` safety net (`logger.exception` + generic error). CLI exits: `0` success, `1` any platform errored, `2` config/user errors.
- **Config path resolution**: `config.config_path()` reads `LLM_USAGE_CONFIG` env var, falls back to `./config.toml` (cwd). `store.db_path()` reads `LLM_USAGE_DB`, falls back to `./history.db` (cwd).
- **`env:` prefix**: Credentials in config may be `"env:VARNAME"` — `_resolve_env_value()` in `providers/__init__.py` expands via `os.environ.get`. Applied to `api_key`, `access_key`, `secret_key`. Keeps secrets out of the config file.
- **Volcengine auth**: Uses **AK/SK (AccessKey/SecretKey) + V4 HMAC-SHA256 signing** — NOT Bearer API key. The Bearer `/api/v3/endpoints/{id}/usage` endpoint returns no usage for Coding/Agent Plans (verified against the live API). Self-contained `_sign_v4()` in `volcengine.py` signs OpenAPI calls to `GetCodingPlanUsage` / `GetAFPUsage` (Service=ark, Version=2024-01-01).
- **Volcengine Coding Plan**: Backend returns **percent-only** (`QuotaUsage[]` with `Level`/`Percent`/`ResetTimestamp`, no used/total). Tier table (`VOLCENGINE_LIMITS` for lite/pro) derives `used = percent/100 * limit`. Config `limits` override takes precedence.
- **Volcengine Agent Plan**: Backend returns **absolute values** (`Periods` with `Used`/`Total`/`Percent`/`ResetTimestamp`). Falls back to `AGENT_LIMITS` tier table when `Total` is absent (large/max unverified → `None`).
- **LLM Gateway**: Live provider configured entirely in `config.toml` like every other platform — `base_url` (required) + `api_key` (single-key form). No side config files. Extracts today's USD cost from `usage.today.actual_cost` (fallback: `usage.daily_usage`/top-level `daily_usage` last item, then legacy `cost`). Two modes switched by `use_groups` (`true` = groups only, `false` = single key only, absent = groups win if configured; `false` ignores stored groups): single-key form uses the top-level `api_key`; multiple keys sharing one daily quota use `[[platforms.llm-gateway.groups]]` (`name`, `daily_limit`, `api_keys`/`keys`/`api_key_envs`) instead of the top-level `api_key`; each key may carry a display **name** — `api_keys` entries may be `{"name", "value"}` dicts (plain strings stay nameless) or the `key_names`/`api_key_names` list alias (entry `name` wins); names surface in `UsageEntry.key_breakdown` items (`name`, `None` = fall back to `key#N`/`#N`) consumed by `show --keys`, the web popover, and per-key error messages (`组A 备用：…`); **Web `/config` is group-only**: `CREDENTIAL_FIELDS["llm-gateway"]` is empty, the editor defaults to one group (组1) with one key input + one daily-limit input per group, 「添加共享 Key」 appends keys sharing that group's quota, 「添加组」 adds groups, and saving writes `groups` plus `use_groups = true` (overriding any legacy `use_groups=false`); the card also edits `base_url` (PUT `base_url` is gateway-only: non-empty string writes, empty = keep; view returns it). Each key row has an optional Key 名称 input (empty = keep existing name; API `name: ""` clears, `name: null` keeps); PUT accepts `{"index", "value", "name"}` per key — new keys are plain strings or `{"name", "value"}` objects, preserved keys resolve through the existing raw entries (named dicts keep their name). Legacy top-level single-key form (`api_key` + optional `daily_limit` + `use_groups`) stays supported by the provider for hand-edited `config.toml`; the web view synthesizes it as one group (组1) and the first save migrates it to `groups` (empty `groups` PUT → 400). `usage_path` etc. stay hand-edited in `config.toml`. each group fans out one request per key (`ThreadPoolExecutor`, capped at `MAX_KEY_WORKERS=8`) and sums the successful keys' `actual_cost` into one `UsageEntry` per group. Duplicate keys within a group are stably de-duped; a key assigned to more than one group is a config error. Per-key failures become `PlatformResult.warning` (never raised) as long as at least one key in a group succeeds; a group with zero successes contributes no entry; all groups failing (or the single key failing) sets `PlatformResult.error`. A non-`None` `warning` means the aggregate is partial, so `store.save_snapshot()` skips it — partial data is never persisted as a full historical snapshot.
- **SQLite reserved word**: The `snapshots` table quotes `"limit"` as a column name (it's a SQLite keyword) in schema, INSERT, and SELECT.
- **Timezone convention**: `reset_at` (UsageEntry) and snapshot `ts` are stored as ISO 8601 **UTC** (`Z`/offset suffix; naive treated as UTC). All terminal display converts to the machine's local time via `display._to_local_time()` (panel title included); JSON output keeps the raw UTC values.
- **Reset countdown**: The overview table's `重置倒计时` column (right-aligned) shows the time until `reset_at` via `display._fmt_countdown()` — computed from the system clock at render time so the TUI ticks live; past → `已重置`, missing/unparsable → `-`. The `BAR_SPAN_WIDTH` geometry puts the bar + percent label right edge at the right-aligned status column's right edge (see the comment above `BAR_SPAN_WIDTH`); the label shows the percent rounded to an integer.
- **Manual entries (contract only)**: no manual provider exists today — all 6 registry keys are live HTTP providers. The `is_manual` flag survives as data contract (`UsageEntry`, provider protocol, snapshot schema/JSON output; historical manual snapshots keep `is_manual=1`). Limit semantics in `models`: `limit=None` → unlimited/unknown (`compute_remaining`/`compute_percent` both return `None`); `limit=0` → `compute_remaining` returns `0.0` (clamped), only `compute_percent` returns `None`.
- **Display color thresholds**: `RED_THRESHOLD=95.0`, `YELLOW_THRESHOLD=80.0` — percent cell colored red/yellow/green accordingly.
- **Naming**: Provider classes `XxxProvider`; test classes `TestXxx`; test methods `test_descriptive_snake_case`.
- **Statelessness**: Provider instances are singletons in the registry; no per-call state except the injected `httpx.Client`.

## Runtime/Tooling Preferences

- **Python ≥3.11** required — uses stdlib `tomllib` for TOML reads. Writes use `tomli_w` (stdlib has no TOML writer).
- **Runtime deps**: `httpx>=0.27`, `rich>=13.0`, `click>=8.1`, `tomli_w>=1.0` — pinned with `>=` floors only, no upper bounds. Optional extras: `test` (pytest), `web` (`fastapi>=0.110`, `uvicorn>=0.29`), `dev` (ruff, mypy) — install via `pip install -e ".[test,web,dev]"`.
- **Package manager**: `pip` (editable install). `uv`/`uvx` available on the system as alternatives. No lockfile committed.
- **Build backend**: `setuptools.build_meta` (`setuptools>=68.0`), src-layout (`packages.find where=["src"]`).
- **Entry points**: console script `llm-usage = "llm_usage.cli:main"` and `python -m llm_usage` — both call the same `cli.main()`.

## Testing & QA
- **Framework**: pytest ≥7.0 (optional dependency via `[project.optional-dependencies] test`; `test_web.py` additionally needs the `web` extra and is skipped without fastapi). Configured in `pyproject.toml` with `testpaths = ["tests"]`.
- **Run**: `python -m pytest tests/ -v` — 238 tests, ~12s, no network. The autouse `_fast_pbkdf2` fixture (conftest.py) monkeypatches pbkdf2 iterations down so auth tests don't pay the real 600k-iteration hashing (~18s → ~12s suite).
- **No coverage config, no markers, no tox.** Only CI is `.github/workflows/docker.yml` (Docker image build/publish to GHCR).

### Test isolation patterns

- **`tmp_config_path`** fixture (`conftest.py`): `monkeypatch.setenv("LLM_USAGE_CONFIG", tmp_path/"config.toml")` — redirects config I/O to temp.
- **`tmp_db_path`** fixture: same pattern with `LLM_USAGE_DB` — isolates SQLite per test.
- **`_clear_api_keys`** (autouse): `monkeypatch.delenv` for `KIMI_API_KEY`/`VOLCENGINE_API_KEY`/`VOLCENGINE_ACCESS_KEY`/`VOLCENGINE_SECRET_KEY`/`OLLAMA_API_KEY`/`OPENCODE_GO_API_KEY`/`LLM_GATEWAY_API_KEY` — prevents real keys leaking into provider tests.
- **`_fast_pbkdf2`** (autouse): monkeypatches `store.PBKDF2_ITERATIONS` down to a token value so user-creation/login tests skip the real 600k-iteration hashing (~18s → ~12s suite).
- **HTTP mocking**: `httpx.MockTransport(handler)` injected via `client=` kwarg in provider constructors. Handler functions assert request URL/headers and return canned `httpx.Response`. No network, no external services.
